# 07-revflow（冲流台）

冲流台 — 正向与冲正流水净额归并：正向装载 → 冲正关联入账 → 净额归并落余额 → 未平/超额隔离 → 流水净额与余额互证。

**不是** 多源 Feed 归并，**不是** 作业依赖编排，**不是** CDC 变更流，**不是** 质检签发，**不是** 数仓分层建设，**不是** 交班过户。  
**也不是** 收银/退款 CRUD 后台、电商订单、报表 CSV 看板——主链是**流水管道与净额状态**，不是业务单据编辑台。

## 主链

账户登记 → 装载正向流水 → 装载冲正并关联原单 → 跑净额归并（已配平落余额，未平/超额进隔离）→ 互证报告核对「流水净额 vs 账户余额」

## 未平隔离原因码与策略

隔离原因不是自由文本，而是有限原因码；每个原因码绑定一个互斥策略。策略落库为**原因码 + 版本**的只追加策略表（`quarantine_policies`，`UNIQUE(reason_code, version)`），「当前策略」= 该码最大版本：

| 原因码 | 含义 | 默认策略 |
| --- | --- | --- |
| `NO_ORIGINAL` | 无原单 | 自动可再配 |
| `ACCOUNT_MISMATCH` | 账户不一致 | 需确认后可再配 |
| `OVER_EXCESS` | 超额 | 永久拒绝 |
| `AMOUNT_INVALID` | 金额非法 | 永久拒绝 |
| `UNCLASSIFIED` | 旧自由文本无法映射的兜底 | 永久拒绝 |

### 策略落库与决策路径（二选一，本仓取第一种）

- **策略落库**：策略表按 **原因码 + 版本** 只追加；改策略 = 追加新版本，**绝不 UPDATE 历史版本行**。隔离行同时钉死 `policy_at_quarantine + policy_version` 快照。
- **决策路径**：**决策行钉死策略版本，再配只追加新决策不改旧行**。每轮复扫按当前版本作新决策并追加一条策略证明；已「已再配」行的处置字段由数据库触发器钉死，任何回溯改写被 `ABORT`。
- 因此：策略版本一处变更**不驱动历史处置行改写**，只影响变更后的新决策。

### 再配门禁（fail-closed）

- 归并每轮复扫「未平」隔离，按**当前**策略执行：自动可再配放行；需确认项无确认标记一律拦住；永久拒绝永不触达余额。
- 策略执行与配平同一事务：任一失败**整笔回滚**（余额、隔离处置、策略证明、运行记录均无半截状态），并落一条「失败」归并运行。
- 确认标记物化为 `quarantine_confirmations`（隔离项唯一、含确认人、确认时策略与版本快照），可审计、不可重复确认。

### 策略证明（基线所无的新增实体）

`quarantine_policy_proofs` 只追加记录每个隔离决策的 **原因码 / 策略版本 / 动作 / 隔离键**（另含证明键、归并运行、说明、时间），提供只读查询：

| 接口 | 说明 |
| --- | --- |
| `GET /api/quarantine/proofs?quarantine_id=..&policy_version=..&reason_code=..&quarantine_key=..&action=..` | 按隔离 id / 策略版本（及原因码/隔离键/动作）查询证明 |
| `GET /api/quarantine/{id}/proofs` | 某隔离项的完整决策证明链 |
| `GET /api/quarantine/policies/versions?reason_code=..` | 策略版本台账（只追加，标注 `is_current`） |

证明、历史策略版本、已再配行处置字段均有数据库级触发器护栏（UPDATE/DELETE 直接 `ABORT`）。

页面：未平隔离（原因码 + 当前策略/入隔离快照 + 登记确认 + 证明链）/ 隔离策略（维护策略表 + 版本台账 + 策略证明）。**不是**质检签发，**不是**工单审批流。

## 界面约定

页面文案全部中文；入口：总览 / 账户 / 正向流水 / 冲正流水 / 归并台 / 未平隔离 / 隔离策略 / 净额互证。  
视觉：**左轨编号导航 + 右侧账册横线工作面**（Literata / JetBrains Mono，靛蓝强调）；**不是**交班台那种顶栏品牌+横向流程条。
